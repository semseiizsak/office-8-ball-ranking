LigaDesign system v0.1

Liga design system

Everything the Liga app is built from: tokens, components and patterns. Dark first, light as a full second theme. Built on the Office 8-Ball system, standardised and made sport neutral, with feedback components taken from the Simon's Dashboard DS.

Logging takes five secondsOpponent, winner, done. Everything else is optional and comes after.
Black and white firstColour is earned. It means something: win, live, crown, brand. Never decoration.
Big where it mattersRatings, names on the live screen and celebration moments go large. Everyday UI stays calm and dense.
Sport neutralNo balls, nets or tables in the core UI. The sport shows up as an icon and a word.
One system, two themesComponents only read semantic tokens. A theme swaps the tokens, never the components.

Foundations

Colour

Three layers. Primitives are raw values. Semantic tokens say what a value is for and change with the theme. Components only use semantic tokens. Every colour is used solid, no tints, no transparent versions of brand or meaning colours.

Brand

Liga violet#5B3DF5

Use it for the app icon, the league mark, the unread dot, your own row marker, the brand button for one hero action per screen, and brand moments (onboarding, paywall).

Never as text colour on dark (too low contrast), never tinted, never as a win or live signal. Text on violet is always white.

Primary actions stay white on dark and black on light. The brand colour is the accent, not the button colour.

Surfaces and text values follow the theme switch

Meaning

Each meaning colour has a fixed partner for text on top of it. Win is always white text, crown and warning are always black text.

Surfaces and depth

Depth comes from stepping up the surface, not from shadows. Only floating things (tab bar, menus, the log button) cast a shadow. No borders on cards.

Icons

Lucide, stroke 2.25 to match the heavy type. 20 px default, 22 px in the tab bar, 18 px inside small buttons. Icons sit next to text, never replace a label the user has to understand. Emoji are allowed for badges, reactions and fun awards, and nowhere else.

Motion

Ease in out, no overshoot, no bounce. Everyday UI is short. Celebrations may be cinematic (up to 1.4 s) but follow the same curve. Everything respects reduced motion.

Components

Buttons

Always pill shaped. One primary per screen. Heights 52, 44, 36. The minimum touch target is 44 px, small buttons get extra hit area.

VariantUse
PrimaryThe main action of the screen or sheet. White on dark, black on light.
SecondaryEverything else. Surface 2 fill, no border.
BrandAt most one per screen, for a brand moment: create a league, upgrade, join.
GhostLow priority: skip, cancel inside a sheet, show all.
DangerOnly for destructive confirmation, always behind a dialog.
LiveOnly to start or open a live match.

Icon buttons and FAB

Round, 44 px (36 px small). Every icon button has an accessible name. The log button floats above the tab bar and is the fastest way into the core loop.

Pills and chips

Pills show state and are not tappable. Chips are tappable filters. Active state is a solid fill with contrasting text, never a pale tint with a coloured border.

Segmented control and tabs

Segmented control switches a view in place (2 to 4 options). Tabs split a screen into sections, like a profile.

Text inputs

Filled, no border, 48 px, 16 px text (no zoom on iOS). Focus is a 2 px text-colour ring. Errors get a red ring and a message below, never only colour.

        Five durations and one curve cover everything. Pick the shortest one that still reads. Scenes are the only place that may run longer than 400 ms.

          • Use colour solid, with its fixed text partner
          • Keep one primary button per screen
          • Keep touch targets at least 44 px
          • Give every icon button an accessible name
          • Use ease in out, no overshoot
          • Show the stakes before a match is played
          Don't
          • Tint or fade the brand or meaning colours
          • Use red for a loss
          • Use pale pills with a coloured border
          • Use italics or text shadows
          • Put a small label above a title
          • Space out uppercase letters
          • Use dashes, dots or slashes to separate text, use gap or a line break
          • Draw sport objects in the core UI
